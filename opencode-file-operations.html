02 / 工具详解

六个工具，各司其职

📖

read

读取文件内容。支持指定起始行和行数，适合逐段阅读大文件。也可以读取目录结构。

只读 · 无风险
🔍

glob

用通配符模式查找文件路径，如 src/**/*.ts。按修改时间排序，快速定位目标文件。

只读 · 无风险
🦯

grep

在文件内容中搜索正则表达式。底层用 ripgrep，速度快，支持过滤文件类型。

只读 · 无风险
✏️

edit

精确替换文件中的字符串。必须先 read 才能 edit。找不到原文本会报错，防止误改。

修改 · 需谨慎
📝

write

创建新文件或完整覆写已有文件。用于生成全新内容，不适合微调已有文件。

写入 · 需谨慎
💻

bash

执行 Shell 命令。git、npm install、python 等都在这里运行。权限最大、风险最高。

执行 · 高权限
03 / 工作流水线

一次完整的文件操作流程

当你说「帮我给项目加一个 .gitignore」时，OpenCode 内部会按以下顺序调用工具：

1
Glob

扫描项目结构

➡
2
Read

读已有配置文件

➡
3
Grep

检测技术栈特征

➡
4
分析

确定忽略规则

➡
5
Write

生成 .gitignore

opencode · 工具调用日志
// 步骤 1: 扫描项目结构
glob({ pattern: "**/*" })
// → 发现 package.json、node_modules/、dist/

// 步骤 2: 读取已有配置
read({ filePath: "package.json" })
// → 发现使用了 TypeScript + Next.js

// 步骤 3: 检测是否有 .env 文件（含敏感信息）
grep({ pattern: "API_KEY|SECRET", include: ".env*" })
// → 发现 .env.local 存在

// 步骤 4: 生成 .gitignore 文件
write({
  filePath: ".gitignore",
  content: "node_modules/\ndist/\n.next/\n.env*.local\n*.tsbuildinfo"
})

05 / 安全护栏

每个工具都有权限开关

在 opencode.json 中通过 permission 字段控制每个工具的行为：

权限值行为适用工具
"allow"直接执行，无需确认read、glob、grep（默认）
"ask"每次执行前弹出确认框bash（推荐）
"deny"完全禁止使用敏感环境下禁用 write
opencode.json
{
  "permission": {
    "read": "allow",
    "glob": "allow",
    "grep": "allow",
    "edit": "allow",
    "write": "allow",
    "bash": "ask"  // 每次执行前需确认
  }
}

07 / 记住这三条

知识锚点

01

先读后写

OpenCode 的铁律：修改文件前必须先 Read，确保 AI 理解上下文后再动手。

02

权限分级

读操作默认放行，写操作可控，Bash 建议设为 "ask"——越危险的工具，越需要人类确认。

03

精准外科手术

Edit 用字符串精确匹配替换，而非整文件覆写。小改动用 Edit，新建用 Write，批量用 Patch。
